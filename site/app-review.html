JAVA EDITION GAME SERVICE API REVIEW

Bestiary Launcher application details.

This page is intended to give Mojang/Microsoft reviewers a concise description of the third-party application, its authentication design and why it requests Minecraft: Java Edition game service access.

APPLICATION

Bestiary Launcher

A Windows desktop launcher for the Bestiary Rebirth Minecraft community. It installs the community client, manages optional client content and allows players who own Minecraft: Java Edition to authenticate with their own Microsoft account.

AUTHENTICATION

Microsoft Device Code Flow

The launcher requests a device code from Microsoft's consumer OAuth endpoint using the public Application Client ID and scopes XboxLive.signin offline_access. The player completes authentication on Microsoft's website. Bestiary Launcher does not request or receive the Microsoft password.

JAVA OWNERSHIP

Entitlement verification

After Microsoft authentication, the launcher authenticates with Xbox Live and XSTS, exchanges that authorization with Minecraft Services, checks the Minecraft entitlements endpoint and only treats the account as a premium Java account after entitlement/profile retrieval succeeds.

PROFILE

Minecraft profile retrieval

The launcher retrieves the authenticated player's Java Edition profile in order to launch Minecraft with the correct profile name, UUID and authenticated session rather than fabricating a premium identity.

SKIN

Player-initiated skin management

When a premium player explicitly selects and applies a skin, the launcher uses that player's authenticated Minecraft token to update the skin for that same account. The launcher does not provide a way to target another premium player's account.

LOCAL / OFFLINE IDENTITY

Separate server-local mode

The launcher also supports a server-local/offline identity mode for the Bestiary community. That mode is isolated from Microsoft authentication and Java Edition Game Service APIs: it does not request Microsoft/Xbox tokens, does not call Java entitlement/profile services, and does not fabricate an authenticated premium identity. Microsoft account mode remains a separate path and always performs Java Edition entitlement verification before an authenticated profile is accepted.

LOCAL SKIN BRIDGE

No premium API impersonation

In local/offline mode, player-selected skin data is handled through the Bestiary server-local skin bridge. It does not call Minecraft profile skin APIs on behalf of an unauthenticated user. Minecraft skin APIs are used only when the active account is a successfully authenticated Microsoft account.

SERVICE FLOW

Authentication sequence

Microsoft Device Code → Microsoft OAuth token → Xbox Live → XSTS → Minecraft login_with_xbox → entitlements/mcstore → minecraft/profile

Skin operations, when explicitly requested by a Microsoft-authenticated player, use the authenticated Minecraft profile skin service.

SECURITY

Credential handling

No client secret is distributed because this is a public client. Refresh credentials are encrypted locally through operating-system-backed Electron safeStorage. Access tokens remain in the main process and are not intentionally exposed to renderer UI code.

SCOPE

Community launcher only

The application uses Minecraft service access only in Microsoft account mode to authenticate the user, verify Java Edition ownership, obtain the authenticated user's own profile and manage that user's own skin. It does not use these APIs for advertising, account resale, credential collection, impersonation, or to bypass ownership/authentication checks.
