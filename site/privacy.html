PRIVACY

Authentication without collecting Microsoft passwords.

This page describes the data handled by Bestiary Launcher when a player chooses Microsoft-authenticated Minecraft: Java Edition login.

MICROSOFT SIGN-IN

What the launcher does not collect

Bestiary Launcher never asks for, receives, stores or proxies a player's Microsoft password. Sign-in is completed on Microsoft's own authentication pages through Device Code Flow.

Password
Not collected

LOCAL DATA

What may be stored locally

The launcher may retain the selected account mode, Minecraft profile name, Minecraft UUID/XUID, skin metadata, launcher settings and a Microsoft refresh credential required to keep the user signed in. The refresh credential is encrypted through Electron safeStorage using the operating-system-backed protection available on the user's Windows account.

TRANSIENT DATA

What stays in memory

Microsoft, Xbox Live, XSTS and Minecraft access tokens are used only as needed to perform authentication and Minecraft service requests. They are not exposed to the renderer user interface and are not published in Bestiary distribution files.

PUBLIC CONFIG

Application Client ID

The Microsoft Application (client) ID is public configuration, not a credential. Publishing it allows Microsoft to identify the Bestiary Launcher application during public-client authentication.

PLAYER CONTROL

Logout and skin controls

Players can switch back to an offline profile, sign out of Microsoft, select a skin file, apply a skin or reset their skin from the launcher account screen.

DATA SHARING

No sale of authentication data

Bestiary does not sell Microsoft authentication data. Authentication requests are sent to Microsoft/Xbox/Minecraft services for the purposes described on the API review page.
